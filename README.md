Experimental churn-classification baseline with a local training and inference demo. It is not validated for production use or real retention decisions.

## Problem
The bundled dataset is synthetic and generated by `scripts/generate_sample_data.py`. Its `churn` label is generated from a rule using contract type, visits per month, support tickets, tenure, and random noise; it is not a recorded customer outcome.

## Architecture
- Dataset loading + feature split in `src/gym_churn/data.py`
- Preprocessing and model training in `src/gym_churn/train.py`
- FastAPI inference in `src/gym_churn/api/main.py`

See `docs/ARCHITECTURE.md`.

## Local Run
```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .[dev]
python scripts/generate_sample_data.py
python scripts/train_model.py
python scripts/make_model_card.py
uvicorn gym_churn.api.main:app --reload --port 8700
```

## API Spec
- `GET /health`
- `GET /version`
- `POST /v1/predict`

Response envelope:
```json
{
  "status": "ok",
  "data": {},
  "meta": {"app_version": "0.5.0", "latency_ms": null},
  "error": null
}
```

## Evaluation
```bash
python scripts/train_model.py
pytest
```

Running training generates:
- `reports/metrics.csv`
- `reports/metrics.json`
- `reports/model_card.md`

The tracked `reports/metrics.json` and `reports/model_card.md` are metadata-only; there is no tracked `metrics.csv` or model benchmark result. The code compares two classifiers on one stratified validation split, selects by F1, and reports metrics from that same split when training is run. The API returns `churn_score`, the model's uncalibrated `predict_proba` output, plus a model class prediction. It does not measure real retention effects.

`app_version` identifies the running API application; the installable package version is defined separately in `pyproject.toml`. No trained model version is claimed.

## Limitations
- Synthetic generated data only; no external validation or recorded customer outcomes.
- No probability calibration, drift monitoring, or measured retention effect.
- Dataset is generated by the repository; no separate data license is stated.
- The API is a local demonstration and must not be used as a production churn decision system.
